# v26.8 release announcement

Email-ready highlights for the management notification, one list per image family.
This is a summary for humans reading their inbox —
[release-notes.md](../../../docs/01-getting-started/release-notes.md) remains the source
of truth for image contents, and every version named here was read out of the published
image itself. Keep this file out of `docs/`: that tree is what ROCm documentation sources
from this repo, and this copy is internal.

Images: `rocm/primus:v26.8` (built 2026-10-08) and `rocm/jax-training:maxtext-v26.8`
(built 2026-10-01).

## JAX MaxText — `rocm/jax-training:maxtext-v26.8`

- **Upgraded to JAX 0.11.1 and TransformerEngine 2.18** (dev build), on a ROCm 10.2 nightly
- **Pinned MaxText to v26.8**, with about 290 upstream commits
  - including the fix for the FP8 correctness issue
- **Speed regressions from JAX 0.11.1 fixed** with new XLA and HIP settings in Primus defaults
  - MoE top-k routing no longer goes through a slow CUB radix sort
  - Collectives overlap compute again (stream priority restored)
  - Dynamic-slice fusion disabled, so attention's backward pass is no longer recomputed per layer
- **Primus source is no longer bundled** in the image
  - users run it with the matching Primus release branch, which the Primus launcher mounts automatically
- **Your XLA flags are respected** instead of being overridden by Primus defaults

## PyTorch — `rocm/primus:v26.8`

- **Upgraded to ROCm 10.1.0 and PyTorch 2.14**, with TransformerEngine and Flash Attention built from source
- **New models:** ZAYA1-8B and MiniMax-M3
- **New features**
  - Fused FP8/FP4 expert layers for MoE models
  - Distributed-optimizer parameter gather on the GPU's copy engines (SDMA)
  - MuonClip (`qk_clip`) attention-logit clipping for hybrid models
- **Performance:** faster gradient handling and FP4 training; retuned MI355X and MI325X recipes
- **Fixes**
  - A compiler bug that could silently corrupt gradients is now detected and worked around
  - DeepSeek-V4 throughput was over-reported 3.6×; now correct (training was unaffected)

## Held back, and why

Recorded so the next release does not have to re-derive these judgements.

- **The two families are on different ROCm builds.** PyTorch uses the ROCm 10.1.0
  release; JAX uses a 10.2 nightly. The email says each family's own base rather than a
  single "ROCm 10.x" line, which would be wrong for one of them.
- **"Upgraded TransformerEngine" is said only for JAX.** The PyTorch image moves from
  the 2.17.0 wheels to a 2.17.1 source build, which is a change of provenance more than
  of version, so its bullet says "built from source".
- **The MiniMax-M3 throughput number (380 TFLOP/s/GPU) is from an 8-layer proxy**, not
  the full model, so it stays on the release-notes page and out of the email.
- **The JAX regression fixes are described by what they change, not by per-model gains.**
  The measured gains (about 0.8 s/step on DeepSeek-V2-16B, about 10% on Llama-2-7B FP8)
  stay on the release-notes page.
- **ZAYA1-8B and the TorchTitan DeepSeek compile fixes ship from `release/v26.8` only.**
  Their PRs (#1199, #1216) are still open against `main`. Fine to announce as part of
  the release, but they will not be on `main` until those merge.
- **SpecForge is excluded.** It is a new backend, but it runs on its own runtime image,
  not on either published image this email is about.
- **gfx1250 is excluded** pending disclosure, as in v26.7, even though MI455X LoRA-SFT
  proxy recipes are in the release.
- **Two known issues are unconfirmed and stay out:** the JAX `packing=false` loss-curve
  issue (carried from v26.6, never re-tested) and the Mamba 370M hipBLASLt failure on
  MI355X (carried from v26.7, not re-tested on the new hipBLASLt). Both are marked
  NEEDS CONFIRMATION in the recipe pages.
- **The hybrid-config rename (`hylo_*` back to `zebra_*`) is a user action item**, not a
  highlight; it is on the release-notes page and in the Megatron notes.
