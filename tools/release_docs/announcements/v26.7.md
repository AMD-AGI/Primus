# v26.7 release announcement

Email-ready highlights for the management notification, one list per image family.
This is a summary for humans reading their inbox —
[release-notes.md](../../../docs/01-getting-started/release-notes.md) remains the source
of truth for image contents, and every version named here was read out of the published
image itself. Keep this file out of `docs/`: that tree is what ROCm documentation sources
from this repo, and this copy is internal.

Images: `rocm/primus:v26.7` and `rocm/jax-training:maxtext-v26.7`, both built 2026-09-09.

## JAX MaxText — `rocm/jax-training:maxtext-v26.7`

- Built with ROCm 10.0.0, up from ROCm 7.14 — the entire JAX stack is rebuilt, and the plugin wheels are renamed `jax-rocm10-pjrt` / `jax-rocm10-plugin`
- JAX 0.11.0 and TransformerEngine 2.17.0 now built against ROCm 10.0.0
- Wheels now install from the AMD stable repository instead of the ROCm nightly index
- RCCL 2.30.4 taken as shipped in the ROCm 10.0.0 SDK, dropping the custom RCCL rebuild used through v26.6
- Retuned MI300X batch sizes across the MaxText recipes; Gemma4-26B FP8 retuned and its FP8 workaround removed

## PyTorch — `rocm/primus:v26.7`

- Built with ROCm 10.0.0, up from a ROCm 7.15 nightly — PyTorch 2.12.0, TransformerEngine 2.17.0, Triton, torchvision/torchaudio and APEX are all rebuilt against it, with wheels now from the AMD stable repository rather than the nightly index
- DeepSeek-V4 extended to MI308X (CDNA3) with context parallelism at 128K context, previously gfx950-only and limited to 4K, and now supports packed-sequence (THD) SFT
- Added a DLRM-v4 (TorchRec/HSTU) projection workload with MI350X calibration, and an MLPerf Llama 3.1 8B launcher with refreshed MI355X configs
- Performance: fused SwiGLU + fc2 removes one FFN-wide saved activation per MLP layer, fused cross-entropy drops a full logits copy, and the DeepSeek-V4 indexer distillation loss is fused; retuned MI355X defaults for Llama 3.1 8B, GPT-OSS 20B and GDN/KDA 1B
- Correctness fix — v26.6 users should upgrade: gradient accumulation on Primus-Turbo's non-fused weight-gradient path kept only the first microbatch's weight gradients, so affected runs trained on partial gradients
- Known issue: Mamba 370M on MI355X aborts inside hipBLASLt on the weight-gradient GEMM; workaround is `TE_HIPBLASLT_ALGO_SELECTION=1`

## Held back, and why

Recorded so the next release does not have to re-derive these judgements.

- **"Upgraded to JAX 0.11.0 / TE 2.17.0" would be wrong this release.** v26.6 already
  shipped both versions; only the ROCm base moved. The v26.6 and v26.4 emails could lead
  with an upgrade line, v26.7 cannot.
- **No new MaxText capability.** The JAX bullets are stack-and-tuning by necessity. If the
  audience expects a feature line per family, set expectations rather than inflate one.
- **APEX looks like a downgrade** (`1.15.0a0+rocm10.1.0a20260822` → `1.13.0+rocm10.0.0`)
  because v26.6 pulled a ROCm 10.1 nightly onto a 7.15 base. True but misleading, so it is
  not an email line.
- **The JAX `packing=false` loss-curve issue is unconfirmed** on ROCm 10.0.0 — carried over
  from v26.6 and never re-tested. Confirm or drop before asserting it to management.
- **gfx1250 is excluded** pending disclosure, even though the enablement is in the release.
