# MaxDiffusion (JAX) runtime deps for running the `maxdiffusion` backend from a
# bare Primus checkout on the MaxText JAX base image. Kept SEPARATE from
# requirements-jax.txt (MaxText) on purpose: the maxdiffusion stack pins
# transformers/torch versions that we do not want to force onto MaxText runs.
#
# torch/torchvision are installed separately (ROCm wheel index) by
# examples/maxdiffusion/setup_maxdiffusion_env.sh, because they need
# --find-links/--no-index which cannot be mixed with a PyPI resolve here.
#
# transformers 4.57.3 and earlier carry CVE-2026-4372, CVE-2026-5241 and
# CVE-2026-9856; 5.10.0 is the first release fixing all three.
#
# 4.x used to be mandatory here: transformers 5.0 removed every Flax and
# TensorFlow class, and MaxDiffusion imported FlaxCLIPTextModel and
# FlaxT5EncoderModel at module load, so any 5.x resolve broke `import
# maxdiffusion` outright. MaxDiffusion now runs FLUX's text encoders as PyTorch
# models under Torchax and guards its remaining Flax imports, which lifts that
# constraint -- but only from a third_party/maxdiffusion pin that carries those
# changes. Bump the submodule and this line together.
transformers>=5.10.0
